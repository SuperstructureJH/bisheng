# Design: 中粮专版显示大小

**关联**: [spec.md](./spec.md) · [tasks.md](./tasks.md)
**版本**: 中粮专版
**最后更新**: 2026-07-27

## 1. 目标与非目标

目标是用类似浏览器 Command +/− 的整页缩放机制，低成本提供小、标准、大三档显示大小，并在管理后台与工作台共用账号偏好。非目标是为 BISHENG 标品建设通用字体系统、提供键盘快捷键或逐页面维护字号与图标映射。

## 2. 关键约束

- 能力只在 `fontSizeVariant=cofco` 的电脑端部署启用；代码仓默认配置为 `disabled`。
- 账号偏好仍以服务端 `user_preference` 为事实源，本地缓存仅辅助首屏。
- 中粮宿主、操作系统与浏览器缩放均不与 BISHENG 联动。
- 三档固定为内部值 1 / 3 / 5，对应整页 90% / 100% / 110%。
- 历史 1–7 档读取时归并，不做数据库迁移：1–2→1、3–4→3、5–7→5。

## 3. 方案对比与选定

### 决策 1：版本范围

- **备选 A**：BISHENG 标品七档滑杆，中粮三档。
- **备选 B**：BISHENG 标品不发布；仅中粮专版提供三档。
- **选定**：B。
- **原因**：前端评审认为标品通用能力需要较大范围的页面适配，本期只满足明确的中粮三档需求。

### 决策 2：缩放机制与应用视口

- **备选 A**：语义字体、图标和容器 token 分层适配。
- **备选 B**：直接在 `html` 根节点设置 `zoom`。
- **备选 C**：在统一应用层设置整页比例，同时按比例反向扩展应用层的逻辑宽高。
- **选定**：C。
- **原因**：用户与前端确认本期优先降低逐组件适配成本，并接受文字、图标、图片、控件与布局一起变化；但单独缩放 `html` 不会同步改变 CSS 视口单位，小档会留下空白，大档会超出浏览器窗口。
- **实现边界**：
  - `html` 始终保持真实浏览器可视区域，负责裁切应用之外的溢出。
  - `body` 作为统一显示层，使用 `transform: scale()` 整体缩放，并设置为 `100 / scale` 的逻辑宽高；Radix Portal 和业务固定层均位于该显示层内。
  - 两端 `#root`、主布局和工作台全屏卡片使用父容器 `100%` 尺寸，不再以未补偿的 `100vh / 100dvh` 覆盖显示层。
  - 不注入 Command +/− 键盘事件，也不修改浏览器自身缩放值。

### 决策 3：账号偏好存储

- 继续复用独立用户偏好表和 `PUT /api/v1/user/preferences/font-size`。
- 两个 SPA 读取 `/user/info.font_scale_level` 并应用同一账号设置。
- 保存失败回滚至前一档；读取失败使用标准档。

### 决策 4：双入口

- 工作台：个人主菜单右侧弹出独立二级气泡。
- 管理后台：个人主菜单左侧弹出独立二级气泡。
- 两端只展示小、标准、大三项，不显示滑杆、刻度、百分比和额外操作说明。

## 4. 对外契约

| 字段 / 契约 | 类型 | 说明 |
|---|---|---|
| `font_scale_level` | `1 \| 3 \| 5` | 当前账号档位，默认 3；历史 1–7 值读取时自动归并 |
| `PUT /api/v1/user/preferences/font-size` | `{"level": 1 \| 3 \| 5}` | 保存当前登录用户档位；其他值返回 422 |
| `window.APP_CONFIG.fontSizeVariant` | `"disabled" \| "cofco"` | 代码仓默认 `disabled`；中粮部署覆盖为 `cofco` |
| `--bisheng-display-scale` | `0.9 \| 1 \| 1.1` | 统一显示层的实际缩放比例 |
| `--bisheng-display-viewport-width` | `100 / scale vw` | 显示层缩放前的逻辑宽度 |
| `--bisheng-display-viewport-height` | `100 / scale dvh` | 显示层缩放前的逻辑高度 |

## 5. 关键模块职责

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `UserPreferenceService` | 默认值、旧值归并、三档校验和偏好保存 | 不判断部署版本 |
| `fontScale.ts` | 判断版本与桌面端、写入显示比例及反向视口尺寸、账号级缓存和跨组件事件 | 不逐类计算字体或图标尺寸 |
| 两端应用显示层 | 保持物理视口不缩放；统一缩放 BISHENG 应用、Portal 和固定层 | 不让全屏页面自行重新定义浏览器视口 |
| 两端 `FontSizeControl` | 展示三档并完成保存失败回滚 | 不提供滑杆或键盘快捷键 |
| 运行时 `config.js` | 决定当前部署是否显示入口 | 标品不得默认开启 |

## 6. 已知风险与兜底

| 风险 | 兜底 |
|---|---|
| 响应式断点仍由真实浏览器宽度判断，而应用逻辑宽度会随档位变化 | 在 90% / 100% / 110% 三档与 1024px、1440px 窗口执行关键页面回归 |
| 固定定位、Portal 或第三方画布对显示层缩放响应不一致 | 覆盖个人菜单、弹窗、下拉框、模型配置、知识空间和对话输入区；发现问题时优先修通用显示层或容器，不恢复七档 token |
| 标品读取到历史偏好 | `disabled` 分支主动移除显示属性并保持 100% |
| 移动端误应用 | 低于 768px 时能力判定为关闭 |

## 7. 测试与可观测

- 后端：默认值、旧值归并、1/3/5 保存、其他值拒绝。
- 前端：版本开关、三档到 90/100/110 的映射、标品清理、入口显隐和左右气泡。
- 构建：client 与 platform 生产构建。
- 部署：13100 使用中粮覆盖配置，探测隔离环境与共享环境；登录态视觉结果单独记录为 PASS / FAIL / BLOCKED / NOT_RUN。

## 8. 已知坑

- **禁止只缩放 `html`**：CSS `zoom` 或 `transform` 不会把后代中的 `100vh / 100vw` 自动改成浏览器缩放后的逻辑视口。只缩放根节点会导致小档页面不足一屏、大档超出一屏。
- **全屏子页面必须继承父级**：主布局已经提供补偿后的逻辑视口时，工作台白卡、管理后台壳和其他全屏根节点必须使用 `width/height: 100%`；重复使用原始视口单位会绕过补偿。
- **Portal 必须留在统一显示层内**：Portal 若挂到显示层之外，会与主页面产生比例和坐标不一致；当前两端 Portal 默认挂在 `body`，因此 `body` 是显示层边界。
