# Design: 个人字体大小

**关联**: [spec.md](./spec.md) · [tasks.md](./tasks.md)
**版本**: v2.6.0
**最后更新**: 2026-07-24

## 1. 目标与非目标

目标是以账号级偏好和语义 CSS token 驱动管理端、工作台的字体、功能图标、控件容器与导航布局。非目标是缩放整个页面、修改业务内容或联动外部字号。

## 2. 关键约束

- 遵循 `docs/constitution.md` C1–C7。
- 新表需兼容 MySQL 与 DM8，不使用 JSON 或数据库方言专属 upsert。
- 偏好属于全局用户账号而非租户资源，因此随同一用户跨租户复用，不增加 `tenant_id`。
- 标品和中粮版本共用内部 1–7 档；版本差异只决定选择控件和可选档位。

## 3. 方案对比与选定

### 决策 1：账号偏好存储

- **备选**：
  - A. 浏览器 `localStorage`：实现快，但无法跨设备、无法严格按账号保存。
  - B. 独立用户偏好表：满足账号级持久化，后续可扩展更多显示偏好。
- **选定**：B，并在浏览器保留仅用于首屏的账号级缓存。
- **原因**：PRD 明确要求按 BISHENG 账号保存，浏览器缓存不能作为事实源。
- **何时重新考虑**：平台形成统一用户设置服务后，迁入统一服务并保持 API 兼容。

### 决策 2：样式响应方式

- **备选**：
  - A. 根节点整体 `scale()`：接入快，但会放大图片、导致模糊和视口溢出。
  - B. 语义 token + 对现有高频工具类的兼容映射。
- **选定**：B。
- **原因**：可分别控制文字、图标、容器和布局，并保持图片尺寸不变。

### 决策 3：双入口与跨前端同步

- **备选**：
  - A. 只改工作台。
  - B. 工作台与管理后台各自提供入口，两个入口调用同一偏好接口，两端都消费 `/user/info` 中的偏好。
- **选定**：B。
- **原因**：产品口径是当前 BISHENG 账号的电脑端显示偏好；用户在两个产品面都需要找到入口，但不能因此形成两份配置。
- **范围边界**：管理后台本期只增加【字体大小】入口和复用控件，不重做其他尚未完善的个人设置。

## 4. 系统现状

### 4.1 数据流

`/user/info → UserPreferenceService → UserPreferenceRepository → user_preference`

用户拖动或选择档位后，前端先应用 token，再调用更新接口；成功后更新账号级缓存，失败则恢复原档位并提示。

### 4.2 对外字段与接口

| 字段 / 契约 | 类型 | 说明 |
|---|---|---|
| `font_scale_level` | `int` 1–7 | `/api/v1/user/info` 返回的当前账号档位，默认 3 |
| `PUT /api/v1/user/preferences/font-size` | `{"level": int}` | 保存当前登录用户档位 |
| `window.APP_CONFIG.fontSizeVariant` | `"standard" \| "cofco"` | 控件模式，缺省为标品 |

### 4.3 关键模块职责

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `UserPreferenceService` | 默认值、档位校验和偏好保存编排 | 不直接访问 ORM |
| `UserPreferenceRepository` | 双数据库兼容的读取与更新 | 不决定产品默认值 |
| `fontScale.ts` | 应用档位、缓存和跨组件事件 | 不直接调用 HTTP |
| 两端 `FontSizeControl` | 在工作台与管理后台个人菜单复用标品滑杆 / 中粮三档交互与失败回滚 | 不维护服务端事实源，不扩展其他个人设置 |

## 5. 已知坑

| # | 反直觉事实 | 如果不知道会怎样 | 在哪处理 |
|---|---|---|---|
| 1 | BISHENG 有两个独立 SPA | 只改一个会在跳转后恢复默认字号 | 两端用户加载链路都应用偏好 |
| 2 | 现有页面同时存在语义类和大量固定 Tailwind 字号 | 只改语义变量会出现局部不响应 | 全局 token + 高频工具类兼容层 |
| 3 | 工作台已有 `fontSize` 本地设置仅服务旧消息显示 | 复用它会变成浏览器级而非账号级偏好 | 新偏好以服务端字段为事实源 |

## 6. 对外契约与依赖

### 6.1 提供

| 契约 | 消费方 |
|---|---|
| `/api/v1/user/info.font_scale_level` | platform、client |
| `PUT /api/v1/user/preferences/font-size` | client、platform 个人菜单 |

### 6.2 依赖

| 依赖 | 风险点 |
|---|---|
| 当前登录用户身份 | 未登录请求必须由现有认证中间件拒绝 |
| 两端全局样式入口 | 工具类新增硬编码时需纳入语义 token 迁移 |

## 7. 测试与可观测

- 后端服务单元测试覆盖默认值、读取和 1–7 档更新。
- 两个前端执行生产构建与相关组件测试。
- 在隔离部署环境分别验证工作台与管理后台个人菜单入口、7 档吸附、刷新保持、跨 SPA 保持、图片不缩放和 1024px 布局。
- 后端访问日志用于确认更新接口状态；数据库 `user_preference` 用于确认账号级持久化。

## 8. 后续改进

- 逐页将剩余固定字号、图标和容器类迁移到明确的语义类。
- 如后续新增主题、密度等个人设置，抽象为统一用户偏好服务。
