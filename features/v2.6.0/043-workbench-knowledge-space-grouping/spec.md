# F043 工作台知识空间下拉分类

## 1. 背景与目标

工作台输入框的【知识空间】下拉列表当前把用户可见空间合并为一个列表，用户无法直接判断空间来源。本需求只增加与知识空间页一致的分类展示，不调整既有搜索、选择、取消选择、输入框提示和已选项展示。

## 2. 范围

### 2.1 本期包含

- 下拉列表按【部门知识空间】→【我创建的】→【我加入的】顺序展示。
- 分类归属与知识空间页保持一致；部门空间不重复出现在后两个分类。
- 搜索沿用现有关键词过滤；搜索后仍按上述顺序分组，没有命中项的分类不展示。
- 桌面端与现有移动端知识空间下拉共用同一分类结果。

### 2.2 本期不包含

- 不修改搜索框提示文案、输入框提示文案或其他既有文案。
- 不修改搜索匹配规则、防抖时间和无结果提示。
- 不修改多选、取消选择、数量上限、已选标签及问答范围。
- 不修改知识空间、成员、权限、邀请或加入流程。
- 不修改 API、数据模型和知识空间页。

## 3. 验收标准

- **AC-01**：打开【知识空间】下拉列表，分类按【部门知识空间】→【我创建的】→【我加入的】排列。
- **AC-02**：部门空间只展示在【部门知识空间】分类，不在后两个分类重复出现。
- **AC-03**：输入关键词后，仅展示存在命中项的分类，分类顺序保持不变。
- **AC-04**：选择和取消选择知识空间的交互与已选项展示保持现状。
- **AC-05**：搜索框提示、输入框提示、无结果提示及其他既有文案保持现状。
- **AC-06**：部署只作用于独立 `13100` 环境，`13000` 与 `3001` 保持可用。

## 4. 技术边界

- 复用现有 `/api/v1/knowledge/space/mine`、`joined`、`department` 三个接口。
- 只调整 `ChatKnowledge` 的客户端数据组织和列表渲染。
- 不新增领域对象、数据库表、接口、权限或错误码。
