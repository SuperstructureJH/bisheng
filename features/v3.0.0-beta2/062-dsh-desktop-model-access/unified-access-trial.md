# Chat / Work 统一模型授权与积分试改

2026-10-20。用户已确认授权、席位、统一积分及网关一起修改，并使用独立分支。当前为本地候选实现，供代码评审和测试环境联调；线上环境和同事原工作区保持原版本。

## 使用方式

管理员进入“积分与使用数据”首页，可以给部门、角色或成员配置每人每月积分，并查看所选时段的积分消耗、Token 明细与使用趋势。“模型权限”页给每个模型设置全员或指定部门、角色、成员可用。两项配置分别保存，Chat 和 Work 共用。

成员在 Chat 输入区、Work 输入区和企业账号设置中看到个人剩余积分。模型列表按权限展示，切换模型继续消费同一余额。界面省略额度来源与席位信息。Work 本机自行配置的外部模型沿用其自有服务，不进入企业账本。

| 规则 | 本版行为 |
|---|---|
| 积分换算 | 100 万 Token = 1 积分；5 亿 Token = 500 积分；输入、输出用量按供应商返回的总量记账 |
| 精度 | 账本保存整数 Token；积分支持 6 位小数，1 Token = 0.000001 分；各模型统一倍率 |
| 周期 | 自然月，采用服务端计费时区，默认 Asia/Shanghai |
| 组织范围 | 部门覆盖子部门；角色与部门按当前成员关系解析 |
| 额度合并 | 启用的个人规则优先，包括 0 分；其余匹配的部门、角色规则取最高值；未命中为 0 |
| 权限与余额 | 模型可见性独立于余额；0 分仍能看到获授权模型，服务端拒绝新调用 |
| 调整额度 | 保留当月已消费量，新上限立即参与后续调用判断 |
| 结算 | Chat 每次代理模型调用和 Work 模型调用进入同一个用户账本；工具循环中的多次模型调用分别记账；重复结算幂等 |
| 消耗未知 | 供应商缺少 usage 时进入原有未知用量核对流程，查询失败显示余额暂不可用 |
| 刷新 | Chat 在任务结束、窗口聚焦和每 15 秒刷新；Work 在调用后、模型刷新及界面轮询时更新 |
| 并发边界 | 调用开始时校验剩余量，已接纳的请求完成后按实际量结算；本版允许在途请求导致超额，属于流量控制而非预付硬预算 |

模型权限保存采用版本冲突校验；每次授权及额度变更保存审计。跨企业查询、用户停用、退出、会话过期和刷新凭据重放继续受服务端校验。

## 代码范围与接口

BISHENG 新增模型可见范围、积分规则、变更审计和个人账本恢复版本存储。Chat 模型目录和调用鉴权接入共同策略，Work 沿用同一运行时账本。工作台原模型编辑入口指向统一模型权限；语音、嵌入等技术配置沿用原职责。

新增浏览器接口：

- `GET/PUT /api/v1/dsh/admin/models/{id}/visibility`
- `GET /api/v1/dsh/admin/policy-subjects`
- `GET /api/v1/dsh/admin/credit-rules`
- `PUT /api/v1/dsh/admin/credit-rules/{DEPARTMENT|ROLE|USER}/{id}`
- `GET /api/v1/dsh/me/credits`：返回 limit、used、remaining 十进制字符串、周期和换算比例。

桌面 `/dsh/usage` 返回统一个人账本，指定模型只改变明细范围。桌面只请求一次共享用量，采用登录代次校验，旧账号响应会被丢弃。

网关登录会话直接记录 tenant_id、user_id。访问凭据字段为 iss、aud、sub、tenant_id、session_id、iat、exp、jti；内省校验会话身份、状态和期限。兑换、刷新、退出地址沿用现有地址，刷新轮换在会话事务中完成，重放撤销整个刷新令牌族。

已删除管理端席位页面、逐模型额度控件、席位管理路由，以及网关席位分配、数量限制和回收服务。旧授权恢复与资料回写任务停止注册。历史席位表、旧授权表、用量中的历史席位字段及审计解析保留，用于迁移和追溯；BISHENG 仍保留未注册到运行入口的旧管理辅助类，后续清理可与历史表归档一同处理。

## 迁移与联调顺序

1. 使用独立测试数据库与 Redis，备份三端版本、SQL 和 Redis。先暂停新模型调用，等待在途调用结算、用量投影落库与旧授权待处理任务完成，停用旧席位相关定时任务。
2. BISHENG 执行 Alembic 升级至 `f062_unified_model_access`，新增四张表并允许新用量记录省略历史席位字段。该迁移继承 `f077_subject_id_search_indexes`。
3. 每个企业预览旧 Work 授权迁移。在 `src/backend` 的项目依赖环境中运行：

   ```sh
   python scripts/dsh/migrate_unified_credits.py --tenant-id <企业ID> --actor-id <管理员ID>
   ```

   核对人数、模型数、额度总数后，原命令增加 `--apply`，按企业事务提交。重复执行识别完成标记。已有新策略时要求先处理策略冲突。

4. 旧 Work 有效模型授权转换为成员可见范围，各模型正额度求和转换为个人积分。旧账本恢复版本与历史消耗保留。旧 Chat 独立工作台模型名单和此前 Chat 统计记录不自动导入新账本；管理员须在开放试用前复核 Chat 所需模型范围和新的月度额度。旧成员额度以个人规则导入，改用部门/角色统一管理时，应停用相应个人覆盖规则。
5. 网关按数据库方言执行 `docker/db/update_dsh_unified_access_mysql.sql` 或 `update_dsh_unified_access_dm.sql`。脚本增加会话企业/用户字段，保留旧列与历史记录，并撤销旧格式会话和刷新凭据。脚本按一次性升级执行。
6. 配套启动新网关、BISHENG API/Worker 与桌面分支。成员重新登录，建立新身份会话。BISHENG 已有 DSH 服务配置、共享签名和 Redis 持久化条件继续适用。
7. 使用普通成员、部门管理员和跨企业账号完成下表真实验收后，再扩大试用范围。发生回退时，恢复配套应用版本与升级前 SQL/Redis 快照；Alembic downgrade 保留数据，操作回退以备份为准。
